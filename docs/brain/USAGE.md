# Brain Folder Usage (브레인 폴더 사용법)

이 문서는 `brain` 폴더가 프로젝트 개발 워크플로우에서 어떻게 활용되는지, 그리고 데이터가 어떻게 흐르는지 설명합니다.

## 에이전트의 데이터 참조 및 워크플로우
Antigravity 에이전트는 다음과 같은 흐름으로 브레인 폴더를 활용합니다.

1. **맥락 로드 (Discovery)**: 새로운 세션이 시작되면 `knowledge` 폴더의 KI들을 읽어 프로젝트의 기술 스택과 규칙을 파악합니다.
2. **태스크 선언 (Tasking)**: 사용자의 요청을 받으면 `brain/<id>/task.md`를 생성하여 단계를 정의합니다.
3. **계획 및 승인 (Planning)**: `implementation_plan.md`를 작성하고 `notify_user`를 통해 사용자 승인을 얻습니다.
4. **실행 (Execution)**: 승인된 계획에 따라 실제 코드를 수정합니다.
5. **검증 및 보고 (Verification)**: `walkthrough.md`를 작성하여 증빙 자료(이미지 등)와 함께 최종 결과를 보고합니다.

## 아키텍처 다이어그램 (ASCII)

```text
+---------------------+       +---------------------------+
|   User (Developer)  | <---> |   Antigravity AI Agent    |
+---------------------+       +-------------+-------------+
                                            |
                                            v
                              +---------------------------+
                              |       BRAIN FOLDER        |
                              | (Memory & Documentation)  |
                              +------+-------------+------+
                                     |             |
           +-------------------------v---+     +---v-------------------------+
           |   SESSION-BASED DATA       |     |     GLOBAL KNOWLEDGE        |
           | (task.md, plan.md, etc.)   |     | (metadata.json, guides.md)  |
           +-----------------------------+     +-----------------------------+
```

## 주요 참조 사례
- **어디에서 참조되는가**:
    - `import` 경로나 런타임 코드상에서 이 폴더를 직접 참조하는 경우는 없습니다. (환경 격리)
    - 오직 **에이전트의 내부 로직** 및 **데이터 팀/데브옵스 문서화 과정**에서만 참조됩니다.
- **데이터 계약 (Data Contract)**:
    - 에이전트는 `implementation_plan.md`에 기술된 파일 변경 리스트를 엄격히 준수할 계약을 가집니다.

## 안전한 확장 가이드
- **Do**:
    - 새로운 공통 규칙이 생기면 `knowledge` 섹션에 KI를 추가하십시오.
    - 태스크 진행 시 주기적으로 `task.md`의 상태를 `[x]`로 업데이트하십시오.
- **Don't**:
    - `*.md.resolved` 파일을 직접 수정하지 마십시오 (동기화 오류 유발 가능).
    - 브레인 폴더 내에 API 키나 비밀번호 등 민감 정보를 평문으로 저장하지 마십시오.

## 트러블슈팅 및 디버깅
- **에이전트가 계획을 따르지 않을 때**: `brain/<id>/implementation_plan.md`를 다시 열어(view_file) 현재 경로가 맞는지 재확인 시킵니다.
- **데이터 유실**: 만약 `task.md`가 비어있다면, `logs` 디렉토리나 브라우저 상의 세션 히스토리를 대조하여 마지막 성공 지점을 확인하십시오. (확실하지 않음: 대부분 자동 복구됨)
